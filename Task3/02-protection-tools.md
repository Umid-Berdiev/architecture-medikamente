# 2. Базовые инструменты защиты данных

Инструменты сгруппированы по состоянию данных. Для каждого указано, какие классы из
`01-data-classification.md` он закрывает и где находится в целевой архитектуре (Task 2).

## 2.1. Управление ключами — фундамент для всего остального

Без управляемых ключей шифрование даёт ложное чувство защищённости: ключ рядом с данными или в руках
того же администратора ничего не защищает.

| Элемент | Решение | Пояснение |
|---|---|---|
| Корень доверия | **HSM** (КриптоПро HSM или Рутокен HSM; для нечувствительной к ГОСТ части допустим сетевой HSM с FIPS 140-2 L3) | KEK верхнего уровня, ключи автораспечатывания Vault, корневой CA внутренней PKI, ключи КЭП организации никогда не покидают HSM |
| Центральный KMS | **HashiCorp Vault** (HA в Kubernetes, auto-unseal через HSM/PKCS#11) | Transit Engine — конвертное шифрование полей и объектов без выдачи ключей приложениям; KV — секреты; PKI Engine — внутренняя CA для mTLS; Database Engine — динамические учётные записи БД с TTL |
| Иерархия ключей | HSM KEK → Vault master → ключи доменов (Identity, Clinical, Billing, HR, Analytics-raw, Backup, Audit) → **per-patient DEK** для документов и записей Clinical | компрометация одного домена не раскрывает другие; удаление DEK пациента = crypto-shredding всех его копий, включая бэкапы |
| Ротация | KEK — раз в год и при смене персонала с доступом; ключи доменов — раз в год с rewrap; TLS-сертификаты — 90 дней (внешние), 30 дней (внутренние mTLS); DEK — при компрометации | Vault хранит версии ключей, rewrap выполняется фоновой задачей без простоя |
| Разделение обязанностей | администраторы Vault/HSM ≠ DBA ≠ администраторы бэкапов ≠ разработчики; операции с KEK — по правилу «двух лиц» (Shamir shares у офицера безопасности и CTO) | закрывает R-12: администратор инфраструктуры видит только шифртекст |
| ГОСТ-криптография | **КриптоПро CSP / JCP** для КЭП, ГОСТ TLS и взаимодействия с ЕГИСЗ, ФНС, СФР; **ViPNet / Континент** для межсетевого ГОСТ VPN | применяется там, где этого требуют ФСБ 378 (защита ПДн средствами СКЗИ) и контрагенты; внутри контура допускается AES/TLS 1.3 при обосновании в модели угроз |
| Инвентарь и аудит ключей | Vault audit device → OpenSearch; реестр ключей в каталоге данных (какой ключ какую таблицу/бакет защищает) | каждое использование ключа журналируется; всплеск операций decrypt — алерт |

## 2.2. Шифрование при хранении (at rest)

Три уровня, применяемые по матрице из `01-data-classification.md` (§ 1.4): **том → поле/объект → бэкап**.

| Хранилище | Уровень 1: том | Уровень 2: поле / объект (классы R, частично C) | Классы |
|---|---|---|---|
| Узлы Kubernetes, PV | LUKS/dm-crypt на дисках узлов, ключи запечатаны в TPM 2.0; `StorageClass` с шифрованием (CSI-драйвер хранилища или Ceph/Longhorn encryption); политика «PVC без шифрования запрещён» | — | все |
| PostgreSQL (Identity, Scheduling, Clinical, Billing, CRM, Consent, 1С) | зашифрованный PV | **конвертное шифрование полей** через Vault Transit (AES-256-GCM, ключ домена; `pii.id`, `pii.contact`, реквизиты счетов, повод обращения/диагноз в текстовом виде); **HMAC-SHA-256-индексы** для поиска по телефону/e-mail/документу без хранения открытого значения; альтернатива для прозрачности — TDE-расширение (pg_tde / Cybertec TDE) при наличии сертифицированной сборки; `pgcrypto` — только для миграции унаследованных данных | R, C |
| Объектное хранилище документов (MinIO / S3-совместимое) | зашифрованные диски | **SSE-KMS** с ключом домена через MinIO KES ↔ Vault; per-patient DEK на объект через метаданные; **object lock (WORM)** для заключений и согласий; версионирование; запрет публичных бакетов | R, C |
| Kafka | зашифрованные тома брокеров | **шифрование полей на стороне продюсера** для `pii.med` (библиотека end-to-end шифрования с ключами из Vault, схема в Schema Registry указывает шифруемые поля); короткий retention топиков с ПДн (7 дней), compaction без ПДн | C, R |
| Raw-зона озера (S3) | зашифрованные диски | SSE-KMS **отдельным ключом `analytics-raw`**, bucket policy только для сервисной учётной записи конвейера, lifecycle по retention | R |
| Curated-зона, ClickHouse | зашифрованные диски ClickHouse (`encrypted` disk type) и S3 SSE | — (данные обезличены); при хранении квази-идентификаторов — column codec `AES_128_GCM_SIV` | I |
| OpenSearch (аудит, логи) | зашифрованный PV | индексы аудита в режиме WORM (ILM без удаления, отключённое обновление), подпись дайджестов за сутки | R |
| Vault, etcd Kubernetes | зашифрованный PV + auto-unseal HSM | шифрование секретов в etcd (`EncryptionConfiguration` с KMS-провайдером) | R |
| Резервные копии | — | **pgBackRest** (`repo-cipher-type=aes-256-cbc`, ключ бэкапов из Vault, отдельный от продакшена), **Velero** с restic/kopia-шифрованием для PV и S3, репозиторий с object lock, off-site копия; восстановление проверяется автоматически | наследуют |
| Рабочие станции, ноутбуки | **BitLocker** (TPM + PIN) / **FileVault**; политика через GPO/MDM | роли с доступом к R работают через **VDI** — данные не покидают ЦОД | C, R |
| Мобильное приложение | Keychain/Keystore для токенов, запрет резервного копирования кэша, документы не кэшируются на устройстве | — | C |
| Бумага | сейф, журнал носителей, шредер | — | R |

## 2.3. Шифрование при передаче (in transit)

Правило: **открытых протоколов в контуре нет**; исключения оформляются как риск с датой закрытия.

| Канал | Требование | Инструмент |
|---|---|---|
| Пациент ↔ портал / мобильное приложение | TLS 1.3 (минимум 1.2), только AEAD-наборы (AES-GCM, ChaCha20-Poly1305), HSTS preload, OCSP stapling, certificate pinning в приложении | Ingress + cert-manager (публичная CA), WAF на API Gateway |
| Каналы ↔ API Gateway ↔ доменные сервисы | mTLS с короткоживущими сертификатами внутренней CA | service mesh (Istio / Linkerd) или cert-manager + Vault PKI; политика `PeerAuthentication STRICT` |
| Сервисы ↔ PostgreSQL | `sslmode=verify-full`, клиентские сертификаты или динамические учётные записи Vault, `ssl_min_protocol_version=TLSv1.2` | PostgreSQL TLS, Vault Database Engine |
| Сервисы ↔ S3 / MinIO | HTTPS с внутренней CA, подпись запросов (SigV4) | MinIO TLS |
| Сервисы ↔ Kafka ↔ аналитика | `SASL_SSL` с OAUTHBEARER (Keycloak) или mTLS, ACL на топики, `ssl.client.auth=required` | Kafka TLS listeners, Schema Registry по HTTPS |
| Сервисы ↔ Vault | TLS + аутентификация Kubernetes ServiceAccount (JWT), политики по namespace | Vault Agent Injector / CSI driver |
| Партнёры (лаборатория, ДМС, клиники) | mTLS с клиентскими сертификатами партнёра + OAuth2 client credentials, IP allow-list, схемная валидация, по требованию контрагента — ГОСТ TLS | API Gateway, КриптоПро NGate при ГОСТ TLS |
| ЕГИСЗ, ФНС, СФР, ЭДО | ГОСТ TLS и КЭП по регламентам площадок (СМЭВ, операторы ЭДО) | КриптоПро CSP, сертификаты УЦ Минцифры/аккредитованных УЦ |
| Платёжный провайдер | TLS 1.2+, 3-D Secure, карта вводится на странице/в SDK провайдера — данные карты не проходят через систему | платёжный SDK/redirect, токен платежа |
| Провайдер уведомлений (SMS, push, голосовой робот) | HTTPS, API-ключ в Vault, шаблоны без мед. сведений | Notification Service |
| ККМ ↔ Payment & Fiscal Adapter, ККМ ↔ ОФД | TLS; ККМ в отдельном VLAN; обмен по протоколу ОФД с шифрованием | сетевые политики, прошивка ККМ |
| 1С (клиент ↔ сервер, веб-сервисы, 1С:Шина) | TLS на сервере 1С и веб-сервисах, доступ к файлам базы закрыт | сервер 1С + PostgreSQL TLS |
| Офис ↔ филиалы ↔ площадка размещения | **ГОСТ VPN** (IPsec/ViPNet) на сертифицированных ФСБ криптошлюзах, класс КС2–КС3 по модели угроз; резервные каналы | ViPNet Coordinator / Континент IPC |
| Почта | TLS 1.2+ на коннекторах (opportunistic → enforced для партнёров), S/MIME для внешней переписки с ПДн, DLP-инспекция, запрет вложений класса R | Exchange + DLP-шлюз |
| Wi-Fi и проводная сеть офиса | WPA3/WPA2-Enterprise (802.1X, EAP-TLS), NAC, гостевая сеть изолирована | RADIUS (FreeRADIUS/NPS), коммутаторы с 802.1X |
| Администрирование | SSH/TLS только через PAM-бастион с записью сессий и MFA; RDP наружу закрыт | Teleport или аналог, аппаратные токены |
| Экспорт данных аналитиком | только через шлюз доступа по TLS; скачивание на устройство запрещено политикой | Trino + OPA, VDI |

## 2.4. Защита при обработке (in use)

| Мера | Инструмент | Классы |
|---|---|---|
| Маскирование по умолчанию в интерфейсах; «раскрыть» — отдельное действие с журналированием | портал сотрудника, PDP, pg_anon для динамических масок на уровне БД | R, C |
| Запрет ПДн в логах и трассировках: аннотации `@Sensitive` → фильтр логгера; ingest-pipeline OpenSearch маскирует по regex; алерт при обнаружении | Logback/Jackson фильтры, OpenSearch ingest, SIEM-правило | R, C |
| Секреты и ключи только в памяти процесса, никогда в переменных окружения и образах; дампы памяти запрещены | Vault Agent / CSI, `securityContext`, запрет `ptrace` | R |
| VDI / терминальный доступ для врачей, ресепшена и аналитиков: данные остаются в ЦОД, буфер обмена и печать ограничены | VDI-платформа, GPO | R, C |
| Печать через print-сервер: учёт, водяной знак с ФИО сотрудника и временем, pull-printing по карте | print-сервер, Document Service | R |
| LLM только локальная; RAG на curated-зоне; промпты и ответы проходят DLP и журналируются; обучение на сырых данных запрещено политикой | локальная LLM в Kubernetes с GPU, DLP-правила | I (R запрещён) |
| Защита экрана: автоблокировка, приватизирующие плёнки на ресепшене и в кассе, запрет фото регламентом | GPO, регламент | C |
| Конфиденциальные вычисления (SEV-SNP/TDX) для сервисов Identity и KMS — после MVP, при наличии оборудования | Kubernetes на узлах с поддержкой TEE | R (перспектива) |

## 2.5. Сводка «класс → минимальный набор инструментов»

| Класс | At rest | In transit | In use | Ключи |
|---|---|---|---|---|
| **R** | зашифрованный том + Vault Transit/SSE-KMS per-patient DEK + WORM + шифрованный off-site бэкап | TLS 1.3 / mTLS / ГОСТ VPN / КЭП | маскирование, VDI, запрет в логах, print-учёт | HSM-корень, ключ домена, ротация, аудит, 2 лица |
| **C** | зашифрованный том + шифрование полей для контактов и реквизитов + шифрованный бэкап | TLS 1.2+/mTLS, ГОСТ VPN между площадками, S/MIME для почты | маскирование, BitLocker | ключ домена, ротация |
| **I** | зашифрованный том | TLS 1.2+ | — | платформенный ключ |
| **P** | контроль целостности | TLS | — | подпись релизов |
