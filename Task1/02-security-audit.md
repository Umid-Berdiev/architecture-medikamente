**Архитектурные практики:** Privacy by Design (проактивность, privacy by default, встроенность в дизайн,
полная функциональность, сквозная защита жизненного цикла, прозрачность, уважение к пользователю);
Data Minimization; Data Lineage; принцип наименьших привилегий и разделение обязанностей; Zero Trust
(«сеть не доверенная», проверка каждого запроса); defence in depth; OWASP API Security Top 10 (для будущих
интеграций); ISO/IEC 27001 (Annex A) и 27701 как чек-листы.

## 2.4. Что это означает для бизнес-потребностей

* **«Изменить парадигму хранения»** — нельзя закрыть точечными настройками прав на папки: данные
  должны переехать из файлов в сервисы с ролевой моделью, разделением доменов (Identity / Clinical /
  Billing) и тегированием (R-01, R-06, R-11).
* **«Снизить риски утечки»** — главные каналы утечки сегодня: общий диск, почта, теневые копии и
  бумага (R-01, R-05, R-07, R-04, R-20). Технические меры без организационных (R-17) не дадут
  юридической защиты при проверке РКН.
* **Пятикратный рост и филиалы** умножают число пользователей с полным доступом; без RBAC/ABAC,
  аудита и сегментации (R-12, R-18) риск растёт линейно с числом сотрудников.

Приоритет устранения: сначала **К** (R-01, R-02, R-05, R-06, R-12, R-14, R-17), затем **В**, затем **С**.
План мер и соответствие R → C приведены в `05-controls.md`.
